## When to use

A change introduces a dataset, consumes one it does not own, or changes the shape of one that
already exists; G4 is about to be recorded and needs the contract for every source dataset; or
a dataset is about to be handed to another agent and the receiver needs to know what it is.

## Rules

1. Write one contract per dataset at
   `delivery/changes/<name>/specs/data/<dataset>/contract.md`. `navi-delivery archive` copies
   `changes/<name>/specs/` over `delivery/specs/`, so a contract written there becomes current
   truth when the change closes. A contract written anywhere else under `changes/<name>/` is
   moved into `delivery/changes/archive/<date>-<name>/` and stops being the answer to "what is
   this table".
2. Number contracts `DC-###`, unique across `delivery/specs/data/` and the active change's
   own `specs/data/`, never reused — `navi-delivery propose` refuses a second change in
   flight, so those two trees are the whole namespace. The id is
   what every other artifact cites: a pipeline's inputs and output, a quality check's target,
   a feature's source, and the `artifacts` list of a handoff envelope.
3. Give the contract all eight sections, in order, none omitted: `## Source`, `## Schema`,
   `## Ownership`, `## Freshness`, `## Classification`, `## Produced by`, `## Not fit for`,
   `## Change notice`. A missing section is an unanswered question, not a shorter contract.
4. Give every field a `## Schema` row with five columns: name, type, nullability, domain
   (unit, format, or the enumerated values), and classification. List every field. `…` and
   `plus the usual audit columns` are not rows.
5. Write nullability as `not-null` or `nullable`, and for every `nullable` field state what a
   null means in that column. A null meaning "not yet known" and a null meaning "does not
   apply" are different facts, and a consumer that cannot tell them apart will average them
   together.
6. Write `## Freshness` as a maximum age and the field it is measured at, plus the behaviour
   when the age is exceeded — `max 26 hours, measured at event_ts; the 06:00 read blocks and
   pages the owner`. `Daily` is a schedule, not a guarantee: it says when the job runs, not how
   old the data may be when someone reads it.
7. Name a person in `## Ownership` — the accountable owner, their role, and the escalation
   path when they are unavailable. A team alias is the escalation path, never the owner. G4
   requires ownership, and an alias answers "who do I ask" with "someone".
8. Classify every field in `## Classification` as exactly one of `public`, `internal`,
   `personal`, `special-category`. For every `personal` or `special-category` field, state the
   lawful basis, the retention period, and who may read it. G4 requires PII classified and its
   handling stated; a field left unclassified is treated as `special-category` until someone
   classifies it.
9. Write `## Produced by` as the dataset's provenance: the `PIPE-###` that writes it, every
   upstream `DC-###` it derives from, every transformation that encodes a business rule (with
   where that rule is written down), and the run identifier stamped into each row or partition.
   A consumer asking "where did this number come from" reads this section and stops.
10. Write `## Not fit for` as at least one `NOTFIT-###`. Each names a use the dataset does not
    support and the observable fact that rules it out — a sampling decision, a lateness bound,
    a restatement, an imputation, a coverage gap. A contract whose `## Not fit for` is empty is
    refused: every dataset has at least one use it does not support, and an empty section means
    nobody asked rather than that nothing is there.
11. Hand a dataset over by naming its `DC-###` in the handoff envelope's `artifacts` list, and
    nothing more. `navi-skill-handoff-protocol` rule 7 already requires concrete ids; the
    contract is the id. Never copy `## Produced by` or `## Not fit for` into the envelope —
    `handoffs.md` is an append-only chronology and the contract is current truth, so a copy in
    the envelope is a second version that goes stale the day the contract changes.
12. Read `## Produced by` and `## Not fit for` before building anything on a received dataset,
    and name the `DC-###` in the receiving envelope's `artifacts` so the record shows which
    version was read. A `NOTFIT-###` that rules out the intended use is refused work: answer it
    in the thread and return it through `navi-skill-handoff-protocol` with `kind: review`.
13. Evolve additively within a contract version. Adding a `nullable` field, widening an
    enumerated domain, or relaxing a `not-null` on a field nothing reads is additive. Removing
    a field, narrowing a type, making a `nullable` field `not-null`, changing a unit, or
    changing what an existing field means is a new version `DC-###@v<n>` with its own
    `## Change notice`, and the previous version stays readable until that notice expires.
14. State a real window in `## Change notice`: the number of days, the date the notice was
    sent, and every consumer notified by name. A notice window with no consumer list notifies
    nobody, and the first the consumer hears of the change is a failed job.
15. Record every contract before G4 is recorded. `cli/lib/lanes.js` gives `standard` the fixed
    set `G1, G2, G3, G5, G6, G7, G8` and `navi-delivery gate` refuses any gate outside the
    lane's set, so a data change on `standard` has no G4 to pass — the contract is written and
    nothing records it. Take the `full` lane at proposal time under `navi-skill-lane-selection`;
    discovering the data touch mid-change is a re-proposal, not a lane edit.
16. Pass G4 with one file. `navi-delivery gate` accepts exactly one `--evidence` value and
    checks only that it resolves, while G4's evidence list names the contracts, the lineage
    document and the baseline evaluation report. Write
    `delivery/changes/<name>/evidence/g4-data-model.md` as an index linking each `DC-###`, the
    pipeline document and the evaluation, and pass that path.

## Decision table

| Observed condition | Required action |
|---|---|
| The change reads a dataset it does not own | Write or cite its `DC-###`; an uncontracted source cannot pass G4 |
| The change writes a new dataset | New `DC-###` with all eight sections before anything consumes it |
| A field's null means "unknown" in some rows and "n/a" in others | Two columns, or one column plus a stated reason code — not one ambiguous null |
| The freshness answer is "it runs nightly" | Not a guarantee — write the maximum age, the field measured, and the behaviour on breach |
| The owner offered is a team alias or a distribution list | Not an owner — name the accountable person and keep the alias as escalation |
| A field's classification is unknown | Treat as `special-category` and block until someone classifies it |
| A field is `personal` | Record lawful basis, retention and readers in `## Classification` |
| `## Not fit for` is empty | Refuse the contract — name at least one unsupported use and the fact behind it |
| A dataset is being handed to another agent | Name the `DC-###` in the envelope's `artifacts`; copy nothing |
| The receiver's intended use is ruled out by a `NOTFIT-###` | Refuse the work; escalate with `kind: review` |
| A field is being added and is `nullable` | Additive — same contract version, note it in `## Change notice` |
| A field is being removed, retyped, or re-meant | New `DC-###@v<n>` with a notice window and both versions readable |
| An upstream owner will not commit to a change-notice window | The source has no contract — record it as an unmitigated dependency and escalate |
| The change is on the `standard` lane and touches a dataset | Re-propose on `full`; `standard` cannot record G4 at all |
| G4 is about to be recorded | Pass `evidence/g4-data-model.md`, the index — not a single contract file |
| An imputation or default fills a source gap | Declare it in `## Produced by` and give it its own `NOTFIT-###` |

## Template

Copy into `delivery/changes/<name>/specs/data/session-events/contract.md`:

```markdown
# DC-003 — session_events

Version: v2 (supersedes v1, readable until 2026-11-15)
Storage: `warehouse.analytics.session_events`, partitioned by `event_date`

## Source

Emitted by `identity-service` on every session create, refresh and destroy. One row per
event, at-least-once delivery; duplicates are collapsed on `event_id` by PIPE-004.

## Schema

| Field | Type | Nullability | Domain | Classification |
|---|---|---|---|---|
| `event_id` | string | not-null | UUIDv4 | internal |
| `event_ts` | timestamp | not-null | UTC, ISO-8601, millisecond precision | internal |
| `event_date` | date | not-null | partition key, derived from `event_ts` in UTC | internal |
| `user_id` | string | not-null | UUIDv4, joins `DC-001.user_id` | personal |
| `event_type` | string | not-null | `created` \| `refreshed` \| `destroyed` | internal |
| `client_region` | string | nullable | ISO-3166-1 alpha-2; null means the edge did not resolve a region, never "unknown country" | internal |
| `theme` | string | nullable | `light` \| `dark`; null means the user has set no preference, not that the default was applied | internal |
| `ingest_run_id` | string | not-null | the PIPE-004 run that wrote the row | internal |

## Ownership

- **Accountable owner:** Dan Okafor, Data Engineering
- **Escalation:** `#data-platform` rota, then Priya Raman, Head of Platform
- **Upstream owner:** Maya Lindqvist, Identity Service — committed to the notice window below

## Freshness

Maximum age 26 hours, measured at `event_ts` against the partition's latest row. On breach
PIPE-004 fails the run, writes nothing downstream, and pages the accountable owner. The 26
hours is the 24-hour cadence plus the two-hour late-arrival bound PIPE-004 allows.

## Classification

| Field | Class | Lawful basis | Retention | Readers |
|---|---|---|---|---|
| `user_id` | personal | contract performance | 400 days, then hashed in place | analytics-read, ml-train |
| everything else | internal | — | 400 days | analytics-read, ml-train, support-read |

`client_region` is not treated as personal on its own; joined to `user_id` it is, so the
combination is only readable by the two roles above.

## Produced by

- **Pipeline:** PIPE-004 (`delivery/changes/theme-persistence/pipeline.md`), run mode
  `incremental-merge` on `event_id`
- **Upstream:** DC-001 (`user_directory`) for the `user_id` domain only — no columns joined
- **Business rules encoded:** a `refreshed` event within 30 seconds of a `created` event for
  the same `user_id` is dropped as a client retry. The 30-second figure is ADR-011.
- **Run stamp:** every row carries `ingest_run_id`; the run log is
  `warehouse.ops.pipeline_runs`

## Not fit for

- **NOTFIT-001 — Counting distinct users per day before 2026-04-01.** `user_id` was hashed
  per-session before that date, so distinct counts over the older partitions count sessions,
  not people. Observable: `SELECT COUNT(DISTINCT user_id)` on 2026-03 partitions exceeds the
  known account total.
- **NOTFIT-002 — Geographic reporting.** `client_region` is null for 8.4% of rows in the last
  90 days, and the nulls are not uniformly distributed — they concentrate in corporate proxy
  ranges. Any regional share computed from this column understates those regions.
- **NOTFIT-003 — Training a model on `theme` as a label after 2026-07-02.** The theme default
  changed that day; rows either side of it mean different things, and the column does not
  record which default was in force.

## Change notice

- **Window:** 30 days for a breaking change, 0 days for an additive one
- **This version:** v2 sent 2026-10-16, effective 2026-11-15. Change: `client_region` becomes
  `nullable` (it was `not-null` with a `ZZ` sentinel in v1), and the sentinel is removed.
- **Consumers notified:** `navi-agent-machine-learning-engineer` (feature `region_share`),
  the Growth dashboard (Maya Lindqvist), the finance extract (Ana Costa)
```

## Checklist

- [ ] The `DC-###` is unique across `delivery/specs/data/` and cited by every consumer
- [ ] All eight sections are present, in order
- [ ] Every field has a schema row; no `…` and no "plus audit columns"
- [ ] Every `nullable` field states what its null means
- [ ] `## Freshness` gives a maximum age, the field it is measured at, and the breach behaviour
- [ ] `## Ownership` names a person, not an alias
- [ ] Every field carries a classification; every `personal` field has basis, retention and readers
- [ ] `## Produced by` names the `PIPE-###`, the upstream `DC-###`s, the encoded rules and the run stamp
- [ ] `## Not fit for` carries at least one `NOTFIT-###` with an observable fact
- [ ] Any breaking change is a new `DC-###@v<n>` with a dated notice and a named consumer list

- [ ] The lane is `full`, because `standard` cannot record G4
- [ ] `evidence/g4-data-model.md` exists and links every contract

## Anti-patterns

**The schema dump.** A contract that is the `CREATE TABLE` statement pasted in. It has types
and nothing else — no meaning for a null, no freshness, no owner, no limits. A consumer can
already read the types from the warehouse; the contract exists for the six things the
warehouse does not know.

**`nullable: yes`.** The column is nullable and the reader is left to infer why. Somebody
eventually writes `COALESCE(client_region, 'unknown')` and a proxy range becomes a country.
Write what the null means: `null means the edge did not resolve a region`.

**Freshness as a cron line.** `Freshness: runs at 02:00 daily.` That is when the job starts,
not how stale the data may be when read at 09:00 after a failed run and a retry. Write the
maximum age, the field it is measured at, and what happens on breach.

**The alias owner.** `Owner: #data-platform.` At 3am the alias has 40 members and no rota, and
the question "was this column meant to be null" has no addressee. Name the person; keep the
alias as escalation.

**Silent breaking change.** The `ZZ` sentinel removed from `client_region` in a Tuesday deploy
because "nothing should have been relying on a sentinel". Three dashboards were. Cut a new
`DC-###@v<n>`, send the notice, keep v1 readable until it expires.

**Empty `## Not fit for`.** `Not fit for: n/a.` This says the dataset supports every use, which
is never true and is believed by the next reader. Name the sampling decision, the lateness
bound, the restatement, or the coverage gap that a user will trip over.

**The handoff that restates the contract.** An envelope carrying a paragraph of provenance and
a list of caveats typed out by hand. Three consumers later there are three versions of the
caveats and two of them are out of date. Name the `DC-###`; the contract is the copy.

**Classification by omission.** Fifteen fields classified and one left blank because nobody was
sure. The blank one is a free-text `notes` column that users put phone numbers in. Unclassified
means `special-category` until classified, and the contract does not pass until it is.

**The uncontracted source.** A join against a table somebody else owns, with no contract,
because "it has been stable for two years". Stability is not a commitment; the first schema
change arrives as a 3am failure. Record it with an owner and a notice window, or record it as
an unmitigated dependency and escalate.

## Validation

```bash
CHANGE=<name>
SPECS=delivery/changes/$CHANGE/specs/data

# Every contract is in the folded subtree, and nowhere else in the change
find delivery/changes/$CHANGE -name contract.md -not -path "*/specs/data/*" \
  | sed 's/^/contract outside the folded specs subtree: /'

for c in $(find "$SPECS" -name contract.md 2>/dev/null); do
  # All eight sections, in order
  for s in Source Schema Ownership Freshness Classification "Produced by" "Not fit for" "Change notice"; do
    grep -q "^## $s\$" "$c" || echo "$c: missing section '## $s'"
  done

  # A DC id, and at least one NOTFIT
  grep -qE '^# DC-[0-9]{3,}' "$c" || echo "$c: no DC-### heading"
  awk '/^## Not fit for$/{on=1;next} /^## /{on=0} on' "$c" | grep -q 'NOTFIT-[0-9]\{3,\}' \
    || echo "$c: '## Not fit for' carries no NOTFIT-###"

  # Schema rows only — `\|` inside a cell means column splitting is unreliable, so the
  # whole row is matched rather than a field index, and the pass is scoped to '## Schema'.
  awk '/^## Schema$/{on=1;next} /^## /{on=0}
       on && /^\| *`/ {
         match($0, /`[^`]+`/); f = substr($0, RSTART, RLENGTH)
         if ($0 ~ /\|[[:space:]]*nullable[[:space:]]*\|/ && $0 !~ /null means/)
           print FILENAME ": " f " is nullable and does not say what null means"
         if ($0 !~ /\|[[:space:]]*(public|internal|personal|special-category)[[:space:]]*\|[[:space:]]*$/)
           print FILENAME ": " f " has no classification in the last column"
       }' "$c"

  # Freshness is a duration, not a schedule
  awk '/^## Freshness$/{on=1;next} /^## /{on=0} on' "$c" \
    | grep -qE '(second|minute|hour|day)s?\b' || echo "$c: '## Freshness' states no maximum age"
done

# Every DC-### a handoff envelope names actually exists
for id in $(grep -hoE 'DC-[0-9]{3,}' delivery/changes/*/handoffs.md 2>/dev/null | sort -u); do
  grep -rqs "^# $id " delivery/specs/data delivery/changes/*/specs/data \
    || echo "handoff names $id, which no contract defines"
done

# No envelope copies contract text. Rule 11 forbids the copy, not the reference: a pointer
# to a section is how a reader finds it. A reproduced section heading, or a NOTFIT-### with
# its body restated, is the copy that goes stale the day the contract changes.
grep -nE '^ *#{1,6} +(Produced by|Not fit for) *$' delivery/changes/*/handoffs.md 2>/dev/null
grep -nE 'NOTFIT-[0-9]{3,} +[-—]' delivery/changes/*/handoffs.md 2>/dev/null

# The lane can actually record G4 — only 'full' can
LANE=$(python3 -c 'import json;print(json.load(open("delivery/.adlc/state.json"))["lane"])')
[ "$LANE" = full ] || echo "lane is '$LANE' — G4 is enforced only on 'full'; re-propose before recording G4"

# G4 evidence is the index, not a single contract
test -f delivery/changes/$CHANGE/evidence/g4-data-model.md || echo "no G4 evidence index"
```

Each command prints nothing when the rule holds, except the lane check, which prints which of
the two situations applies. The `find` for contracts outside `specs/data/` is the one worth
running early: a contract in the wrong directory passes every other check here and then
disappears into the archive the day the change closes.
