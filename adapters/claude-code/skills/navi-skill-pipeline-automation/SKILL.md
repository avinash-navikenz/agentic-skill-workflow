## When to use

A change has no defined path to an environment; a deployment cannot be traced back to a commit
or an artifact; a pipeline stage was skipped and the run still reported green; a secret has
appeared in a build log; or G7 is about to be recorded and needs the run record, the rollback
rehearsal and the artifact identity.

## Rules

1. Write the pipeline definition at `delivery/ops/delivery-pipeline.md`, one file per
   deployable. It belongs under `ops/` because it outlives every change: `navi-delivery
   archive` folds `changes/<name>/specs/` into `delivery/specs/` and renames the rest of the
   change away, so a pipeline described inside a change stops being current truth the day it
   archives.
2. Number stages `STAGE-###` in execution order, unique across `delivery/ops/`, never reused. A
   stage that is removed is marked `retired` with a date, not deleted — a reader of an old
   release record otherwise cannot find the stage it names.
3. Give every stage seven fields: `Runs`, `Triggered by`, `Consumes`, `Produces`,
   `Fails the pipeline when`, `Duration budget`, `Owner`. All seven, on every stage.
4. Build the deployable artifact exactly once, and promote that same artifact by digest through
   every environment. Record the digest. A rebuild per environment produces a different
   artifact from the one that was verified, and G7's reproducibility criterion is then recorded
   against something nobody tested.
5. Record three identities for every release: the commit SHA, the artifact digest, and the
   pipeline run URL. A run id alone expires with the CI provider's retention policy, and a tag
   can be moved; a digest and a SHA cannot.
6. Pin every tool the pipeline invokes to a version or a digest — base images, actions,
   task versions, language runtimes, linters. `latest` makes yesterday's green run
   unreproducible, and the first symptom is a failure nobody changed anything to cause.
7. Reference secrets, never embed them. Every stage that reads a secret names it and the store
   it comes from, and no stage echoes one. A secret that has reached a build log is
   compromised: rotate it and record the rotation — redaction changes what is displayed, not
   what was stored.
8. Fail closed. A stage that cannot reach a dependency fails the pipeline; it never skips and
   reports green. `continue-on-error`, `|| true` and an unconditional `exit 0` are the three
   ways a verification stage becomes decorative, and all three leave the run green.
9. Make every stage re-runnable from the same inputs with the same result. A stage that
   succeeds only on a clean runner, or only the first time, is a stage nobody can re-run during
   an incident, which is the hour it will be needed.
10. Keep the pipeline identical on every lane. `cli/lib/lanes.js` gives each lane a fixed gate
    set — `express` records G2, G6, G7; `hotfix` records G2, G6, G7, G9 — and the lane decides
    which gates are recorded, never which stages run. A hotfix that skips the build's own
    verification is how the fix becomes the second incident.
11. Deploy every environment by the same stage. Environment differences live in versioned
    configuration whose diff between two environments can be printed on demand. A separate
    production deploy path is an untested path used only under pressure.
12. Make rollback a stage, not a document: a `STAGE-###` that redeploys the previous recorded
    digest, invoked by one command. G7 requires a rollback that has been exercised and whose
    time-to-restore is known, and a paragraph describing one has neither property.
13. Rehearse the rollback and record the date and the measured time-to-restore in
    `## Rollback rehearsals`. A rehearsal older than the most recent change to the deploy path
    is not evidence about the current path.
14. Record every manual step as `MANUAL-###` with an owner and the task that removes it, except
    the four human checkpoints, which are decisions rather than steps — see
    `navi-skill-human-checkpoints`. An unrecorded manual step is performed differently at 03:00
    by whoever is awake.
15. Quarantine a flaky stage with an owner and a date; never add a blanket retry. A retry in
    the pipeline configuration does what `references/gates.md`'s G6 criterion forbids a person
    from doing by hand — re-running until green — and does it invisibly on every run.
16. State a `Duration budget` per stage and the total. A pipeline slower than the interval
    between changes becomes a queue, and a queue is where changes get batched into one release
    whose blast radius nobody sized.
17. Pass G7 with one file. `navi-delivery gate` accepts exactly one `--evidence` value and
    checks only that the path resolves, while G7's evidence list names the pipeline run record,
    the rollback rehearsal record and the release approval. Write
    `delivery/changes/<name>/evidence/g7-release.md` as an index linking all three, and pass
    that path.

## Decision table

| Observed condition | Required action |
|---|---|
| The pipeline is described inside a change directory | Move it to `delivery/ops/delivery-pipeline.md`; `archive` renames the change away |
| Each environment builds its own artifact | Build once, record the digest, promote that digest |
| The release record names only a CI run id | Add the commit SHA and the artifact digest |
| A step pins `latest` or an unpinned base image | Pin a version or a digest before the next release |
| A secret is passed as a literal in the pipeline file | Replace with a store reference, rotate the secret, record the rotation |
| A secret appears in a build log | Rotate it — redaction hides the display, not the value |
| A stage carries `continue-on-error` or `\|\| true` | Remove it; a stage that cannot verify must fail the run |
| A stage passes only on a clean runner | Make it re-runnable from the same inputs, or it is unusable in an incident |
| The lane is `hotfix` and stages are being skipped | Run every stage; the lane changes which gates are recorded, not which stages run |
| Production has its own deploy path | Collapse to one stage plus versioned configuration whose diff is printable |
| Rollback exists only as a written procedure | Make it a `STAGE-###` invoked by one command |
| The last rollback rehearsal predates a change to the deploy path | Rehearse again; the old measurement describes a path that no longer exists |
| A manual step is being performed every release | Record `MANUAL-###` with an owner and the task that removes it |
| A stage is flaky and a retry was added | Remove the retry, quarantine the stage with an owner and a date |
| A stage has no duration budget | Add one, and the total; an unbudgeted pipeline becomes a queue |
| G7 is being recorded | Pass `evidence/g7-release.md`, the index — not the run URL |

## Template

Copy into `delivery/ops/delivery-pipeline.md`:

```markdown
# Delivery pipeline — web-shell

Definition of record: `.github/workflows/delivery.yml` (this file describes it; that file runs
it, and the two are reviewed together). Total duration budget: 21 minutes.

## Stages

### STAGE-001 — Build

- **Runs:** `docker buildx build --provenance=true -t web-shell:$GITHUB_SHA .`
- **Triggered by:** every push to any branch, and every pull request
- **Consumes:** the commit, `package-lock.json`, base image
  `node:22.11.0-bookworm-slim@sha256:0f1a...` (pinned by digest)
- **Produces:** one OCI image, pushed by digest to `ghcr.io/example/web-shell`. The digest is
  the only identity used downstream; no environment rebuilds.
- **Fails the pipeline when:** the build exits non-zero, or the lockfile is not in sync with
  `package.json`
- **Duration budget:** 4 minutes
- **Owner:** Ana Costa

### STAGE-002 — Unit and contract tests

- **Runs:** `npm test -- --reporter=junit`
- **Triggered by:** STAGE-001 succeeding
- **Consumes:** the image from STAGE-001, by digest
- **Produces:** `reports/junit.xml`, retained for 90 days and copied into the change's evidence
- **Fails the pipeline when:** any test fails, or the report is empty. An empty report fails:
  a suite that collected nothing is not a suite that passed.
- **Duration budget:** 6 minutes
- **Owner:** Ana Costa

### STAGE-003 — Dependency and secret scan

- **Runs:** `npm audit --audit-level=high --omit=dev` and `gitleaks detect --no-banner`
- **Triggered by:** STAGE-001 succeeding
- **Consumes:** `package-lock.json`, the working tree
- **Produces:** the advisory list read by `navi-skill-dependency-vulnerabilities`
- **Fails the pipeline when:** either tool exits non-zero. Neither is wrapped in
  `continue-on-error`.
- **Duration budget:** 2 minutes
- **Owner:** Priya Raman

### STAGE-004 — Deploy

- **Runs:** `./deploy.sh --env "$ENV" --digest "$DIGEST"`
- **Triggered by:** STAGE-002 and STAGE-003 succeeding. For `production`, additionally by the
  recorded release approval — see `navi-skill-human-checkpoints`; the pipeline does not
  simulate it.
- **Consumes:** the digest from STAGE-001; `config/$ENV.yaml`, versioned in this repository.
  `diff config/staging.yaml config/production.yaml` is the whole difference between the two
  environments and is printed into the release record.
- **Produces:** a running revision, recorded as `<env> <digest> <revision>` in the release
  record
- **Fails the pipeline when:** the health check does not pass within 120 seconds of the new
  revision receiving traffic
- **Duration budget:** 5 minutes
- **Owner:** Ana Costa

### STAGE-005 — Rollback

- **Runs:** `./deploy.sh --env "$ENV" --digest "$PREVIOUS_DIGEST"`
- **Triggered by:** manual invocation by the incident commander, or automatically by a halt
  condition in `delivery/changes/<name>/rollout.md`
- **Consumes:** `PREVIOUS_DIGEST`, read from the release record — never from a tag, which can
  be moved
- **Produces:** the previous revision serving traffic, and a row in `## Rollback rehearsals`
  when invoked as a rehearsal
- **Fails the pipeline when:** the previous digest is absent from the registry, which means the
  retention policy has deleted the thing this stage exists to restore
- **Duration budget:** 4 minutes, which is also the time-to-restore this stage commits to
- **Owner:** Ana Costa
```

## Checklist

- [ ] `delivery/ops/delivery-pipeline.md` exists and is not inside a change directory
- [ ] Every `STAGE-###` carries all seven fields
- [ ] One artifact is built and promoted by digest; no environment rebuilds
- [ ] The release record carries a commit SHA, an artifact digest and a run URL
- [ ] Every tool, action and base image is pinned to a version or a digest
- [ ] Every secret is a store reference; the `## Secrets` table names the store and last rotation
- [ ] No stage carries `continue-on-error`, `|| true` or an unconditional `exit 0`
- [ ] Every stage is re-runnable from the same inputs
- [ ] The same stages run on every lane
- [ ] One deploy stage serves every environment, with versioned per-environment configuration
- [ ] Rollback is a `STAGE-###` invoked by one command, reading a digest and not a tag
- [ ] A rollback rehearsal is recorded, dated after the last change to the deploy path
- [ ] Every manual step is a `MANUAL-###` with an owner and the task that removes it
- [ ] No blanket retry; any flaky stage is quarantined with an owner and a date
- [ ] Every stage has a duration budget and the total is stated
- [ ] `evidence/g7-release.md` exists and links the run record, the rehearsal and the approval

## Anti-patterns

**Rebuild per environment.** `staging` builds from `main`, `production` builds from `main` an
hour later, and the base image moved in between. The thing verified and the thing serving
traffic are different artifacts with the same tag. Build once; promote the digest.

**The tag as identity.** The release record says `v2.4.1`. Someone force-pushes the tag. The
record now points at code that did not ship. Record the digest and the SHA, which cannot move.

**`continue-on-error: true` on the scan.** It was added the week the scanner was noisy and
never removed. The pipeline has been green through four advisories. A verification stage either
fails the run or does nothing.

**The retry that hides a race.** `retries: 3` on the integration stage. It passes on the second
attempt about a third of the time, and nobody has looked at why for eight months. Quarantine
the stage with an owner and a date; a retry is re-running until green with the evidence
deleted.

**The special production path.** Staging deploys through the pipeline; production is a script
somebody runs from a laptop with an exported credential. The path used when it matters most is
the one with no test coverage and no audit trail. One stage, versioned configuration.

**Rollback as a paragraph.** `## Rollback: redeploy the previous version.` Nobody has run it,
the previous image was garbage-collected at 30 days, and the time-to-restore is unknown. Make
it a stage, rehearse it, record the measurement.

**The secret that was redacted.** A token was printed, the log was scrubbed, and the ticket was
closed. The value still exists everywhere the log was shipped in the interim. Rotate it and
record the rotation.

**`latest` in the base image.** Six weeks of green runs, then a red one on a commit that
changed a comment. The base image moved. Pin by digest and upgrade deliberately.

**The pipeline nobody can run twice.** The deploy stage appends to a file it does not truncate,
so the second run doubles the configuration. It has only ever been run once per commit, and the
first time anyone re-runs it is during an incident. Re-runnability is a property to test, not
to assume.

## Validation

```bash
CHANGE=<name>
P=delivery/ops/delivery-pipeline.md
CI=.github/workflows          # or the directory holding your own pipeline definitions

test -f "$P" || echo "no delivery/ops/delivery-pipeline.md"

# Every stage carries all seven fields
for id in $(grep -o 'STAGE-[0-9]\{3,\}' "$P" | sort -u); do
  body=$(awk -v id="$id" '$0 ~ "^### " id " " {on=1; next} /^### /{on=0} on' "$P")
  [ -n "$body" ] || { echo "$id: named in the file but has no '### $id — …' entry"; continue; }
  for k in Runs "Triggered by" Consumes Produces "Fails the pipeline when" "Duration budget" Owner; do
    printf '%s\n' "$body" | grep -q "\*\*$k:\*\*" || echo "$id: missing $k"
  done
done

# A rollback stage exists and reads a digest rather than a tag
grep -q 'PREVIOUS_DIGEST\|previous recorded digest\|previous digest' "$P" \
  || echo "no rollback stage reading a previous digest"

# A rehearsal is recorded, and it is dated
awk '/^## Rollback rehearsals$/{on=1;next} /^## /{on=0} on' "$P" \
  | grep -qE '[0-9]{4}-[0-9]{2}-[0-9]{2}' || echo "no dated rollback rehearsal recorded"

# Every secret named in the pipeline file appears in the secrets table with a store
awk '/^## Secrets$/{on=1;next} /^## /{on=0} on' "$P" | grep -q '|' \
  || echo "no ## Secrets table"

# Nothing in the pipeline definition suppresses a failure
grep -rn -e 'continue-on-error: *true' -e '|| true' -e 'ignore_errors' "$CI" 2>/dev/null \
  && echo "a pipeline step suppresses its own failure"

# Nothing is pinned to a floating reference
grep -rnE ':latest|@main\b|@master\b|uses: *[^@]+$' "$CI" 2>/dev/null \
  && echo "a pipeline step uses a floating version"

# No literal secret in the pipeline definition
grep -rnE '(password|secret|token|api[_-]?key) *[:=] *["'\'']?[A-Za-z0-9/+_-]{16,}' "$CI" 2>/dev/null \
  && echo "a literal that looks like a secret is in the pipeline definition"

# No blanket retry
grep -rnE '^\s*(retries|max_attempts|retry): *[0-9]+' "$CI" 2>/dev/null \
  && echo "a blanket retry is configured; quarantine the flaky stage instead"

# Every manual step has an owner and a removal task
awk '/^## Manual steps$/{on=1;next} /^## /{on=0} on' "$P" \
  | grep '^| MANUAL-' \
  | awk -F'|' '$4 ~ /^[[:space:]]*$/ || $5 ~ /^[[:space:]]*$/ {print "manual step with no owner or no removal task:"$2}'

# The release record carries all three identities
EV=delivery/changes/$CHANGE/evidence/g7-release.md
test -f "$EV" || echo "no G7 evidence index at $EV"
if [ -f "$EV" ]; then
  grep -qE 'sha256:[0-9a-f]{8,}' "$EV" || echo "$EV: no artifact digest"
  grep -qE '\b[0-9a-f]{40}\b|Commit: *`[0-9a-f]{7,}' "$EV" || echo "$EV: no commit SHA"
  grep -qE 'https?://' "$EV" || echo "$EV: no pipeline run URL"
  grep -q 'time-to-restore' "$EV" || echo "$EV: no measured time-to-restore"
  grep -qi 'approved by' "$EV" || echo "$EV: no named release approver"
fi
```

Each command prints nothing when the rule holds. The digest check on the release record is the
one to run before G7: it is the only mechanical difference between a deployment that can be
reproduced and one that can only be described.
