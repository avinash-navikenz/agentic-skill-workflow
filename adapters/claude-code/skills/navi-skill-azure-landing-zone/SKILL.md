## When to use

A workload is about to be given somewhere in Azure to live; production and staging share a
subscription and the quota they also share is about to run out; a policy was assigned on one
subscription and the subscription created last week does not have it; resources are being named
by whoever created them; a cost report cannot be split by workload because nothing is tagged; or
a deployment is being denied by a rule nobody can find because it was created in the portal.

## Rules

1. Record the topology at `delivery/ops/azure/landing-zone.md`, one file per tenant. It belongs
   under `ops/` because it outlives every change: `navi-delivery archive` renames a change away,
   and a subscription layout described inside one stops being current truth the day it archives.
2. Assign every policy at a management group, never at a subscription. A management-group
   assignment reaches a subscription created next month on the day it is created; a
   subscription-scoped assignment has to be remembered by whoever creates the next one, and the
   first evidence that it was not is a non-compliant production resource.
3. Give production its own subscription. A resource group is not a security, quota or billing
   boundary: subscription-scoped Owner, subscription quota, and a policy exemption all cross it,
   so a resource group inside a shared subscription gives production none of the separation the
   diagram appears to show.
4. Give every subscription a `SUB-###` row naming its management group, its environment, a
   person as owner, a monthly budget as a number, and the percentage at which the budget alerts.
   A subscription with no budget has no blast radius in money, and the first notification is the
   invoice.
5. Give every resource group a row naming its subscription, its lifecycle and the condition
   under which it is deleted. A group with no stated end is never deleted, and the cost of what
   is left in it is charged to whoever inherits the subscription.
6. Deploy resource groups from `infra/azure/platform/main.bicep` at `targetScope =
   'subscription'` — a resource-group-scoped deployment cannot create one — and give them
   literal names. A name assembled from parameters cannot be read against the convention before
   it is deployed, which is the only time reading it is cheap.
7. Name every resource by the patterns in `## Naming` and nothing else. Record the pattern per
   resource type, because Azure's own rules differ per type: a storage account and a container
   registry take no hyphens and no upper case, a resource group takes both, and a convention
   that ignores that is a convention half the estate cannot follow.
8. Apply the full required tag set in the template, and enforce the same set with a `Deny`
   policy. The template is the source and the policy is the backstop; a tag applied only by a
   `Modify` policy arrives after the resource exists, so every report built on it is wrong for
   as long as the remediation task takes.
9. Never hardcode a subscription id, tenant id or object id in a template. A GUID in the file is
   a template that can only be deployed into the tenant it was written for, and the first
   disaster-recovery rehearsal in a second tenant is where that is discovered.
10. Give every `param` an `@description`, and an `@allowed` wherever the value set is closed. A
    parameter whose legal values live only in a reviewer's memory is a parameter that will be
    given `Prod` where `prd` was meant, and the name that results passes no pattern.
11. Record every assignment as `POL-###` in `## Policy assignments` with its scope and its
    enforcement mode, and keep the deployable form in `infra/azure/policy/assignments.json`. The
    register is what a reviewer reads; the JSON is what runs. A policy created in the portal is
    in neither, and a deployment it denies is denied by a rule nobody can find.
12. Assign in `Default` enforcement. `DoNotEnforce` audits and permits, so an assignment left in
    it is a rule the estate is not actually under; every one needs a dated row in
    `## Exemptions` naming who accepted the risk and when the exemption ends.
13. Give every management group that holds a subscription at least one assignment, at it or
    above it. A management group with no policy above it is a subscription with no policy, and
    the tree makes it look otherwise.
14. Give every `deployIfNotExists` or `modify` assignment a managed identity and a `location`.
    Without both, the assignment deploys, reports compliant-by-omission, and remediates nothing.
15. Keep what the platform owns out of the workload subscriptions. The registry, the shared
    build identity and the log workspace live in the platform subscription; a workload
    subscription holds only what that workload runs, so retiring a workload cannot delete
    something another workload depends on.
16. Put a `reviewBy` date in the required tag set and a `Review by` date on every assignment. A
    tag schema and a policy set are both decisions that expire, and an estate governed by
    decisions nobody has revisited is governed by the person who left.

## Decision table

| Observed condition | Required action |
|---|---|
| A policy is assigned on a subscription | Move it to a management group; the next subscription inherits it automatically |
| Production and staging share a subscription | Split them; a resource group is not a quota, policy or Owner boundary |
| A subscription has no budget | Add the figure and the alert percentage to its `SUB-###` row |
| A subscription's owner is a team alias | Name a person |
| A resource group has no stated deletion condition | Add it, or say `permanent` and name who reviews it |
| `main.bicep` has `targetScope = 'resourceGroup'` and creates resource groups | Change to `subscription`; a resource-group deployment cannot create one |
| A resource group name is assembled from parameters | Make it literal in the platform template |
| A name does not match its type's pattern | Rename it; the pattern differs per type because Azure's own rules do |
| A required tag is applied by a `Modify` policy only | Apply it in the template too; remediation arrives after the resource exists |
| A template contains a subscription, tenant or object GUID | Replace it with a parameter |
| A `param` has no `@description` | Add one, and an `@allowed` if the value set is closed |
| A policy was created in the portal | Move it into `assignments.json` and give it a `POL-###` row |
| An assignment is `DoNotEnforce` | Record a dated row in `## Exemptions`, or set it to `Default` |
| A `deployIfNotExists` assignment has no identity or no location | Add both; without them it remediates nothing and reports compliant |
| A management group holding a subscription has no assignment at or above it | Assign one; the tree is not itself a control |
| The registry or log workspace sits in a workload subscription | Move it to the platform subscription |
| An assignment or the tag set has no review date | Add one; a governance decision nobody revisits is owned by whoever left |

## Naming

Every name is `<type>-<workload>-<environment>-<region>`, lower case. Types that Azure forbids
hyphens in run the segments together; the pattern per type is the authority, not the sentence.

| Resource type | Prefix | Pattern |
|---|---|---|
| Resource group | rg | `^rg-[a-z0-9]{3,12}-[a-z]{3}-[a-z]{3}$` |
| Container app | ca | `^ca-[a-z0-9]{3,12}-[a-z]{3}-[a-z]{3}$` |
| Key vault | kv | `^kv-[a-z0-9]{3,12}-[a-z]{3}-[a-z]{3}$` |
| Managed identity | id | `^id-[a-z0-9]{3,12}-[a-z]{3}-[a-z]{3}$` |
| Log Analytics workspace | log | `^log-[a-z0-9]{3,12}-[a-z]{3}-[a-z]{3}$` |
| Container registry | cr | `^cr[a-z0-9]{5,20}$` |
| Storage account | st | `^st[a-z0-9]{5,20}$` |

// Resource groups for the web-shell workload, deployed once per subscription.
// Subscription scope, because a resource-group deployment cannot create a
// resource group. Register: delivery/ops/azure/landing-zone.md.

targetScope = 'subscription'

@description('Azure region the resource groups are created in.')
@allowed([
  'westeurope'
  'northeurope'
])
param location string = 'westeurope'

@description('Finance cost centre every group in this deployment is billed to.')
param costCentre string

@description('Person accountable for what runs in these groups. Not a team alias.')
param owner string

@description('Date the existence of these groups is next reviewed, as YYYY-MM-DD.')
param reviewBy string

// Literal names, so the convention in ## Naming can be read against them before
// anything is deployed. A name assembled from parameters is only reviewable
// after the fact, which is when reviewing it is expensive.
var groups = [
  {
    name: 'rg-webshell-prd-weu'
    purpose: 'the running workload'
    dataClassification: 'confidential'
  }
  {
    name: 'rg-webshell-stg-weu'
    purpose: 'pre-production rehearsal of the same deploy path'
    dataClassification: 'internal'
  }
  {
    name: 'rg-webshell-bld-weu'
    purpose: 'container registry and the federated build identity'
    dataClassification: 'internal'
  }
]

var baseTags = {
  workload: 'webshell'
  owner: owner
  costCentre: costCentre
  managedBy: 'infra/azure/platform/main.bicep'
  reviewBy: reviewBy
}

resource workloadGroups 'Microsoft.Resources/resourceGroups@2024-03-01' = [for g in groups: {
  name: g.name
  location: location
  tags: union(baseTags, {
    environment: split(g.name, '-')[2]
    dataClassification: g.dataClassification
    purpose: g.purpose
  })
}]

output groupNames array = [for (g, i) in groups: g.name]

## Anti-patterns

**The policy on one subscription.** `Deny public network access` is assigned to
`sub-contoso-prod-weu`, which was the only subscription when it was written. Two subscriptions
later, two thirds of the estate is uncovered and the compliance dashboard is green because it
reports on the scope the assignment has. Assign at `mg-contoso-workloads`.

**Production as a resource group.** `rg-webshell-prd-weu` and `rg-webshell-stg-weu` in one
subscription, described as separated. A staging load test exhausts the subscription's regional
vCPU quota and production cannot scale out. Give production its own subscription.

**The name nobody can follow.** The convention says `<type>-<workload>-<env>-<region>`, and the
storage account is `st-webshell-prd-weu`. Azure rejects it: storage account names take no
hyphens. Record the pattern per type, so the convention is one someone can satisfy.

**Tags by remediation.** The required tags are applied by a `Modify` policy with a remediation
task. The cost report splits by `costCentre`, and every resource created since the last
remediation run is in the `untagged` bucket. Apply the tags in the template; keep the policy as
the backstop that denies what the template missed.

**The GUID in the template.**

```bicep
param subscriptionId string = '00000000-1111-2222-3333-444444444444'
```

The template now deploys into exactly one tenant. The disaster-recovery rehearsal in the
secondary tenant fails on a value nobody knew was there. Pass it in.

**Audit mode that was going to be temporary.** `enforcementMode: DoNotEnforce` was set to get a
release out, with the intention of flipping it the week after. The compliance report shows the
assignment, and the rule has never once denied anything. Record the exemption with a date, or
set it to `Default`.

**The remediation that never ran.** A `deployIfNotExists` assignment for diagnostic settings,
with no identity and no location. It deploys, it reports, and no resource has ever had a
diagnostic setting created by it. Give it `SystemAssigned` and a `location`.

**The portal policy.** A deployment is denied with a definition id nobody recognises. It was
created in the portal eighteen months ago by someone who has left, it is in no repository, and
working out what it does takes longer than the incident. Keep assignments in
`assignments.json`.
