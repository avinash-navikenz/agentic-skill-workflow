## When to use

A change is about to be built and nobody has said where the testing effort goes; G6 is about to
be entered and its entry criterion asks for a strategy; the suite has grown past the pipeline's
duration budget; or a release decision needs to know what was deliberately left untested.

## Rules

1. Write the strategy at `delivery/changes/<name>/test-strategy.md`, link
   `./test-design.md` from it, and add a row for the strategy to the `## Linked artifacts` table
   that `templates/change/design.md` ships into every `design.md`. The design links the
   strategy; the strategy links the cases.
   Write it at Phase 2, alongside the spec review for testability — `references/gates.md` makes
   it G6's **entry** criterion, so a strategy first written at Phase 6 is written after the
   decisions it was supposed to inform.
2. Number risks `RISK-###`, sequential within the change. Give every risk seven fields:
   `What breaks`, `Who is affected`, `Consequence`, `Likelihood evidence`, `Level`,
   `Covered by`, `Owner`. All seven, on every risk.
3. Assemble the register from three sources and record each source's pass, including the ones
   that produced nothing, as `none` with the reason: the spec's `REQ-###` (what was promised),
   `design.md`'s `## Failure modes` (what the design says can fail), and the threat model's
   `THREAT-###` (what someone would do on purpose). A register drawn from one source
   systematically misses the other two's whole class, and nothing in the artifact reveals it.
4. State `Likelihood evidence` as an observation, never as a number with no origin: a past
   incident and its date, a defect history, a dependency's advisory record, the fact that this
   code path is new, or `first of its kind — no history`. `Medium` is not evidence; it is a
   summary of evidence nobody wrote down.
5. Allocate every risk to the lowest level that can prove it — `unit`, `integration`,
   `contract`, `end-to-end`, `measurement`, or `manual` — and say in one clause why the level
   below cannot. An end-to-end test standing in for a unit test costs its runtime on every run
   forever and localises nothing when it fails.
6. Record what is deliberately not tested in `## Not covered`, each entry naming the risk, the
   reason, and the person who accepted it. A strategy claiming everything is covered is either
   false or describes a suite nobody can run inside the pipeline's budget, and the deliberate
   gap is the one fact a release decision cannot obtain anywhere else.
7. Map every `AC-###` in the change's spec to at least one level, or list it under
   `## Verified manually` with the reason and the named person. G6's exit criterion admits
   manual verification with a recorded reason; it does not admit an unmentioned criterion.
8. Put the negative and empty-state criteria in scope explicitly, at a named level. G6 names
   them, and a strategy that says `full coverage of the acceptance criteria` without them
   reliably produces a suite that exercises the happy path at three levels and the empty case
   at none. `navi-skill-test-design` derives the cases; this file commits the level.
9. Name the environment each level runs in and its fidelity gaps — the ways it differs from
   production that matter to the risks being chased there. A risk chased in an environment that
   cannot express it is an untested risk with a green tick beside it.
10. State the flakiness policy in one line and apply it: quarantine with an owner and a review
    date, never a retry. G6's exit criterion requires exactly this, and a retry in the pipeline
    configuration does the forbidden thing on every run without a record — see
    `navi-skill-pipeline-automation` rule 15.
11. Plan the non-functional measurements. Every non-functional `AC-###` names the instrument and
    the conditions it holds under, taken from the matching `QAS-###` in `design.md` under
    `navi-skill-quality-attributes`. G6 requires those thresholds measured rather than assumed,
    and an instrument chosen at Phase 6 measures whatever is convenient.
12. Carry each `THREAT-###`'s `Verify` line into the strategy as a `measurement` or
    `integration` entry. `navi-skill-threat-modelling` writes that line at Phase 3 precisely so
    G6 has something to run; a strategy that omits it leaves G6's security criterion with no
    scheduled work.
13. Size the suite against the pipeline's stated duration budget in
    `delivery/ops/delivery-pipeline.md`. A suite that exceeds it becomes a nightly run, and a
    nightly run gates nothing — the merge happened sixteen hours earlier.
14. Never state coverage as a line or branch percentage. Coverage is stated per risk and per
    criterion; a line percentage rises when a test asserts nothing and falls when dead code is
    deleted, so it moves in the wrong direction on both of the changes that matter.
15. Re-run the allocation when the lane changes or the design's failure modes change. A
    strategy written against a `standard` change that is re-proposed on `full` gains G4's data
    and model risks, and nothing recomputes it.
16. Write the strategy on every lane. `cli/lib/lanes.js` enforces G6 on all four —
    `express` records G2, G6, G7 and `hotfix` records G2, G6, G7, G9 — so no lane omits it. On
    `express` and `hotfix` it is shorter, not absent.
17. Pass G6 with one file. `navi-delivery gate` accepts exactly one `--evidence` value and
    checks only that the path resolves, while G6's evidence list names the test report, the
    defect list and the security verification record. Write
    `delivery/changes/<name>/evidence/g6-quality.md` as an index linking all three plus this
    strategy, and pass that path — see `navi-skill-release-readiness` for what that index says.

## Decision table

| Observed condition | Required action |
|---|---|
| The strategy is being written at Phase 6 | Too late — it is G6's entry criterion; write it at Phase 2 |
| The register was drawn only from the requirements | Run the failure-mode and threat passes too, recording `none` where empty |
| A likelihood is stated as `medium` | Replace with the observation: an incident and its date, a defect history, or `first of its kind` |
| A risk is allocated to end-to-end | Say why unit, integration or contract cannot prove it; otherwise move it down |
| The strategy claims everything is covered | Write `## Not covered` with the risk, the reason and who accepted it |
| An `AC-###` appears at no level | Allocate it, or list it under `## Verified manually` with a reason and a person |
| Only the happy-path criteria are allocated | Put the negative and empty-state criteria at a named level |
| A risk is chased in an environment that cannot express it | Name the fidelity gap; the tick is not evidence |
| A flaky test is being retried | Quarantine it with an owner and a review date |
| A non-functional `AC-###` has no instrument | Take it from the matching `QAS-###`; measured, not assumed |
| A `THREAT-###` has a `Verify` line and no strategy entry | Add it as a `measurement` or `integration` entry |
| The suite exceeds the pipeline's duration budget | Re-allocate downward, or say plainly that the suite no longer gates the merge |
| Coverage is being reported as a percentage | Report per risk and per criterion |
| The lane changed | Re-run the allocation; a `full` change carries data and model risks a `standard` one did not |
| The lane is `express` or `hotfix` | Still write it — G6 is enforced by every lane |
| G6 is being recorded | Pass `evidence/g6-quality.md`, the index — not the test report |

## Template

Copy into `delivery/changes/<name>/test-strategy.md`, and add its row to `design.md`'s
`## Linked artifacts` table:

```markdown
# Test strategy — theme-persistence

Lane: `standard` (G1, G2, G3, G5, G6, G7, G8). Pipeline duration budget: 21 minutes, of which
this suite may take 8 — see `delivery/ops/delivery-pipeline.md` STAGE-002.
Cases: `./test-design.md`. This file decides the levels; that one decides the cases at them.

## Source pass

| Source | Risks drawn | If none, why |
|---|---|---|
| `spec.md` REQ-### | RISK-001, RISK-002, RISK-003 | — |
| `design.md` `## Failure modes` | RISK-004, RISK-005 | — |
| `threat-model.md` THREAT-### | RISK-006 | THREAT-002 and THREAT-003 were designed out at G3 and have no build to exercise. THREAT-001's control is the session layer's, unchanged by this change; its `Verify` line runs at G6 against the existing security suite and draws no new risk here. |

## Risks

### RISK-001 — The stored preference is not applied on first render

- **What breaks:** a returning user sees the default theme rather than the one they chose
- **Who is affected:** every returning user with a stored preference — about 61% of daily
  sessions, roughly 500,000 a day
- **Consequence:** the feature silently does nothing; the complaint arrives as "it forgot
  again" and is indistinguishable from the bug this change exists to fix
- **Likelihood evidence:** the same defect shipped in 2026-04 (INC-2261) when the read happened
  after first paint; the ordering constraint is unchanged
- **Level:** integration — the render path and the preference store have to meet, and a unit
  test of the resolver cannot observe paint ordering
- **Covered by:** AC-011, AC-012
- **Owner:** Sam Idowu

### RISK-002 — An absent `prefers-color-scheme` header resolves to nothing

- **What breaks:** first render for a client that sends no header
- **Who is affected:** ~4% of sessions, about 33,000 a day, concentrated in older embedded
  browsers and one enterprise tenant's kiosk fleet
- **Consequence:** a blank or unstyled first render, which is worse than either theme
- **Likelihood evidence:** first of its kind — the resolver is new. The 4% figure is measured
  from 90 days of request logs to 2026-09-20, so the population is known even though the defect
  history is not.
- **Level:** unit — the resolver is a pure function of three inputs and the absent case is one
  of them; nothing above unit adds information here
- **Covered by:** AC-013 (the empty-state criterion)
- **Owner:** Sam Idowu

### RISK-003 — Cross-region preference reads exceed the render budget

- **What breaks:** the preference read from a region that does not hold the primary store
- **Who is affected:** the 23% of sessions served from ap-southeast — about 190,000 a day
- **Consequence:** first render exceeds AC-016's 400ms bound for those sessions, which is the
  criterion this change is measured on
- **Likelihood evidence:** SLI-007 records the store's cross-region p95 at 61ms against 14ms
  in-region over the 90 days to 2026-09-20; the budget has 28ms of headroom
- **Level:** measurement — the integration environment is single-region, so the risk cannot be
  expressed there at all, and a passing integration run would be evidence about nothing
- **Covered by:** AC-016
- **Owner:** Ana Costa

### RISK-004 — The preference store is unreachable at render time

- **What breaks:** the resolver's dependency, not the resolver
- **Who is affected:** every user, for the duration
- **Consequence:** `design.md` `## Failure modes` states the behaviour — fall back to the header
  and do not block paint. Untested, the fallback is a paragraph.
- **Likelihood evidence:** the store's own SLI-007 records three availability dips below
  objective in the 90 days to 2026-09-20
- **Level:** integration, with the dependency faulted — a unit test with a stubbed store proves
  the branch exists, not that paint is unblocked
- **Covered by:** AC-015
- **Owner:** Sam Idowu

### RISK-005 — The store migration cannot be run backwards

- **What breaks:** the rollback route, not the feature
- **Who is affected:** every user, if a rollback is needed after the migration has run
- **Consequence:** `design.md` `## Failure modes` states that the legacy column is retained
  until TASK-034, so rollback is available — untested, that is an assertion rather than a fact
- **Likelihood evidence:** first of its kind — this is the first migration on this table. The
  2026-04 incident INC-2261 was a forward fix for exactly this reason.
- **Level:** manual — running a migration backwards against production-shaped data is a
  rehearsal, not a test, and there is no harness for it
- **Covered by:** AC-015
- **Owner:** Ana Costa

### RISK-006 — A crafted preference value reaches the renderer

- **What breaks:** the boundary CONTRACT-002 draws
- **Who is affected:** any user sharing a session store partition
- **Consequence:** THREAT-004's stated gain — attacker-controlled content in the shell
- **Likelihood evidence:** THREAT-004, dispositioned `mitigated` at G3 with the control named
  in `design.md`
- **Level:** measurement — THREAT-004's `Verify` line, run against the build
- **Covered by:** THREAT-004, AC-018
- **Owner:** Priya Raman
```

## Anti-patterns

**The pyramid with no risks.** `70% unit, 20% integration, 10% end-to-end.` The ratio is a
shape, not a decision — it says nothing about which of this change's failures are covered.
Allocate per risk and let the shape fall out.

**Likelihood as a word.** `Likelihood: medium.` Nobody can check it, nobody can update it, and
it was chosen so the risk would land in the middle of the ranking. Cite the incident, the defect
history, or say there is none.

**Everything at end-to-end.** Twelve browser tests that each start the whole stack, because
they are the tests that look most like a user. The suite takes 40 minutes, fails for
environmental reasons twice a week, and when it goes red nobody can say which component broke.
Push down; keep end-to-end for the journeys that must never break.

**The strategy with no gap.** Every risk covered, every criterion tested, nothing accepted. The
suite that would follow does not exist, so what actually happens is the gaps appear silently
during the build. Write `## Not covered` and get it accepted by a person.

**Happy-path-only allocation.** The criteria are covered; the empty state, the absent header and
the concurrent write are not in the file. G6's negative and empty-state criterion is unmet, and
the missing case is the one that reaches production. Allocate them explicitly.

**The environment that cannot show it.** A cross-region latency risk chased in a single-region
compose stack. The test passes. The risk is untested and now has a tick beside it. Name the
fidelity gap and move the risk to a level that can express it.

**The retry in the config.** `retries: 2` was added the sprint the integration suite got noisy.
Three genuine races have shipped since. Quarantine with an owner and a review date.

**The instrument chosen at Phase 6.** The threshold is p95 under 200ms and the measurement is
whatever tool was to hand, at whatever load the laptop could generate. The number is real and
means nothing. Take the instrument and the conditions from the `QAS-###`.

**Coverage as a percentage.** `Coverage: 84%.` It rose 3 points last week because someone
added assertion-free tests to a generated file, and it will fall when dead code is deleted.
State coverage per risk and per criterion.

## Validation

```bash
CHANGE=<name>
T=delivery/changes/$CHANGE/test-strategy.md
SPEC=$(find delivery/changes/$CHANGE/specs -name spec.md 2>/dev/null | head -1)

test -f "$T" || echo "no test-strategy.md — G6's entry criterion is unmet"
grep -q 'test-strategy.md' delivery/changes/$CHANGE/design.md 2>/dev/null \
  || echo "design.md's Linked artifacts table does not name test-strategy.md"
grep -q 'test-design.md' "$T" 2>/dev/null \
  || echo "test-strategy.md does not link test-design.md, so the cases have no home"



# All three sources appear in the pass
for s in 'REQ-###' 'Failure modes' 'THREAT-###'; do
  awk '/^## Source pass$/{on=1;next} /^## /{on=0} on' "$T" | grep -qF "$s" \
    || echo "source '$s' is not in the source pass"
done

# Every risk carries all seven fields
for id in $(grep -o 'RISK-[0-9]\{3,\}' "$T" | sort -u); do
  body=$(awk -v id="$id" '$0 ~ "^### " id " " {on=1; next} /^### /{on=0} on' "$T")
  [ -n "$body" ] || { echo "$id: named in the file but has no '### $id — …' entry"; continue; }
  for k in "What breaks" "Who is affected" Consequence "Likelihood evidence" Level "Covered by" Owner; do
    printf '%s\n' "$body" | grep -q "\*\*$k:\*\*" || echo "$id: missing $k"
  done
  # Likelihood is an observation, not a rating
  printf '%s\n' "$body" | awk '/\*\*Likelihood evidence:\*\*/{on=1} /\*\*Level:\*\*/{on=0} on' \
    | grep -qiE '[0-9]{4}-[0-9]{2}|INC-|first of its kind|no history|defect|advisory|SLI-|THREAT-' \
    || echo "$id: likelihood evidence names no observation"
  printf '%s\n' "$body" | grep '\*\*Likelihood evidence:\*\*' \
    | grep -qiE '\*\* *(high|medium|low)\.?$' && echo "$id: likelihood is a rating, not evidence"
  # The level is one of the six
  printf '%s\n' "$body" | grep '\*\*Level:\*\*' \
    | grep -qE 'unit|integration|contract|end-to-end|measurement|manual' \
    || echo "$id: Level is not one of unit/integration/contract/end-to-end/measurement/manual"
done

# Nothing is covered without an accepted gap list
awk '/^## Not covered$/{on=1;next} /^## /{on=0} on' "$T" | grep -q '^| ' \
  || echo "## Not covered is empty — a strategy with no deliberate gap has not allocated effort"
# Every not-covered row names an acceptor
awk '/^## Not covered$/{on=1;next} /^## /{on=0}
     on && /^\| / && $0 !~ /^\| Risk/ {
       split($0, c, "|");
       if (c[4] ~ /^[[:space:]]*$/) print "not-covered row with nobody accepting it: " c[2]
     }' "$T"

# Every AC in the change's spec is allocated somewhere
if [ -n "$SPEC" ]; then
  for ac in $(grep -o 'AC-[0-9]\{3,\}' "$SPEC" | sort -u); do
    grep -q "$ac" "$T" || echo "$ac appears in the spec and nowhere in the strategy"
  done
fi

# Every threat with a Verify line has a strategy entry
TM=delivery/changes/$CHANGE/threat-model.md
if [ -f "$TM" ]; then
  for th in $(awk '/\*\*Verify:\*\*/{print prev} {if ($0 ~ /^### THREAT-/) prev=$2}' "$TM" | sort -u); do
    grep -q "$th" "$T" || echo "$th has a Verify line and no entry in the strategy"
  done
fi

# Every non-functional AC names an instrument
awk '/^## Non-functional measurements$/{on=1;next} /^## /{on=0}
     on && /^\| AC-/ {
       split($0, c, "|");
       if (c[4] ~ /^[[:space:]]*$/) print "non-functional AC with no instrument: " c[2]
     }' "$T"

# The suite's wall time is stated against a budget
awk '/^## Suite budget$/{on=1;next} /^## /{on=0} on' "$T" | grep -qE '[0-9]+m|[0-9]+s' \
  || echo "no stated wall time for the suite"

# No percentage coverage claim
grep -nEi 'coverage[^.]{0,20}[0-9]{1,3} *%' "$T" \
  && echo "coverage is claimed as a percentage; state it per risk and per criterion"

# No retry configured anywhere in the pipeline
grep -rnE '^\s*(retries|max_attempts|retry): *[0-9]+' .github/workflows 2>/dev/null \
  && echo "a retry is configured; the flakiness policy forbids it"
```

Each command prints nothing when the rule holds, except the `## Not covered` check on a
strategy that genuinely covers everything — which is worth reading twice before dismissing.
The AC-allocation loop is the one to run before G6: it is the only mechanical link between what
was promised and where anyone intends to look for it.
