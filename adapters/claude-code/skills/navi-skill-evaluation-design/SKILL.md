## When to use

A model is about to be fitted and how it will be judged is not yet written down; G4 is about to
be recorded and needs a held-out, leakage-checked evaluation set with a metric tied to the
outcome; a result looks too good; or a promotion is about to be decided on a number and someone
needs to know how that number was produced.

## Rules

1. Write the evaluation at `delivery/changes/<name>/specs/models/<model>/evaluation.md`, beside
   the framing. `navi-delivery archive` folds `changes/<name>/specs/` into `delivery/specs/`,
   so the evaluation stays readable by whoever promotes, monitors or retires the model.
2. Write and commit the evaluation **before the first model is fitted**, and record the date.
   An evaluation written after a score is a description of that score: the metric, the split
   and the threshold all get chosen knowing which choice flatters the candidate.
3. Describe the split in `## Splits`: which `DC-###` it is drawn from, the rule (time cut-off,
   entity hash, group), the exact boundary value, and the row count of each set. "80/20 random"
   is a rule only where no entity repeats and nothing is about the future.
4. Split by time where the prediction is about the future, and by group where rows repeat an
   entity. Where both hold, split by time and check that no entity crosses the boundary. A
   random row split under either condition puts the answer in the training set.
5. Run the six-prompt **leakage pass** against every evaluation set, and record every prompt —
   including the ones that produced nothing, as `none` with the reason, so "considered and
   empty" is distinguishable from "never asked":
   **time** (a feature computed from data later than the prediction time in `framing.md`),
   **join** (a joined table that encodes the label or its consequence),
   **duplicate** (the same entity or a near-duplicate row in both sets),
   **target** (the label, or a deterministic function of it, among the features),
   **group** (rows belonging to one entity split across sets),
   **preprocessing** (a scaler, encoder, imputer or vocabulary fitted on the full data before
   the split).
   Number each finding `LEAK-###` and state what was changed and what the score did once it
   was fixed. The drop is the size of the leak, and it is the honest number.
6. Give every `EVAL-###` six fields: `Metric`, `Set`, `Threshold`, `Uncertainty`, `Decides`,
   `Serves`. `Decides` names what changes when the number moves — a promotion criterion, a
   gate verdict, an operating threshold. A metric that decides nothing is reported, not
   evaluated.
7. Report an interval, never a bare point. `Uncertainty` names the method and its parameter:
   a bootstrap with the number of resamples, or the analytic interval for a proportion with
   the n it was computed on. A point estimate with no interval cannot be compared to anything.
8. Record a comparison whose difference does not exceed the intervals as `no difference`, in
   those words. A win inside the noise reported as a win is the most common way a model with no
   advantage reaches production.
9. Read the test set once per candidate, at the end. Model selection, hyperparameters and the
   operating threshold are chosen on the validation set. Log every read in `## Test-set reads`
   with the date, the candidate and who read it; a candidate whose test set was read more than
   once has been tuned against it and is re-evaluated on a fresh hold-out before it can be
   promoted.
10. Report per `SLICE-###`, not only in aggregate. Each slice names the field it cuts on, its
    row count, and its own `EVAL-###` rows. A slice below the stated minimum size is reported
    as `underpowered` with its count — never dropped, because the dropped slices are the ones
    the model is worst on.
11. Treat a slice regression beyond its interval as a regression of the whole, even where the
    aggregate improves. Record the gate verdict that reads it as `--fail`; the aggregate is an
    average over people, and the average is not the one complaining.
12. Derive the operating threshold from the cost table in `framing.md` and show the arithmetic
    in `## Operating point`. A threshold of 0.5 is a library default; a threshold of 0.5 with
    the arithmetic that lands on 0.5 is a choice.
13. Name the `BASELINE-###` each `EVAL-###` is compared against, and the margin against the
    interval. An evaluation with no baseline measures a model against nothing.
14. Make the evaluation re-runnable: `## Reproduce` names the command, the random seed, the
    `DC-###` versions, and the code commit — all four. An evaluation nobody can re-run cannot
    be checked at promotion, and `navi-skill-model-registry-and-promotion` refuses a candidate
    whose training run cannot be re-executed.
15. Re-run the evaluation against the build at Phase 6, not only against the notebook. gates.md
    requires G6 to measure the non-functional thresholds named in the spec rather than assume
    them; a model's measured quality is one of them, and the number that matters is the one the
    deployed path produces.
16. Record the evaluation before G4 is recorded. `cli/lib/lanes.js` gives `standard` a fixed
    gate set without G4 and `navi-delivery gate` refuses a gate outside the lane's set, so a
    model change on `standard` has no G4 to pass. Take `full` at proposal time under
    `navi-skill-lane-selection`.

## Decision table

| Observed condition | Required action |
|---|---|
| The prediction is about the future | Split by time; state the cut-off value |
| Rows repeat an entity | Split by group; assert no entity crosses the boundary |
| Both hold | Split by time, then check for entity crossings |
| The result is far better than the best baseline | Run the leakage pass again before believing it |
| A feature is computed from data later than the prediction time | Leakage: remove the feature and re-fit |
| A scaler or vocabulary was fitted before the split | Leakage: re-fit it inside the training fold only |
| Near-duplicate rows appear in both sets | Leakage: deduplicate on the entity, then re-split |
| A leakage prompt produces nothing | Record `none` with the reason; silence is indistinguishable from omission |
| A metric has no interval | Not a result — compute the interval and state the method |
| The difference is inside the intervals | Record `no difference`; the simpler option wins |
| The test set has been read twice for one candidate | Re-evaluate on a fresh hold-out; the old number is tuned |
| A slice is below the minimum size | Report it as `underpowered` with its count; never drop it |
| The aggregate improves and a slice regresses beyond its interval | A regression — record the gate `--fail` |
| The threshold is the library default | Derive it from the cost table and show the arithmetic |
| An `EVAL-###` names no baseline | Add one; a number with no comparison decides nothing |
| `## Reproduce` is missing a seed, a data version or a commit | Not reproducible — promotion is refused on it |
| The change is on the `standard` lane | Re-propose on `full`; `standard` cannot record G4 |

Written 2026-09-18, before the first fit. Framing: `./framing.md`.

Drawn from DC-003 `session_events`, first-render rows only, 2026-03-01..2026-09-01.

| Test | `event_ts >= 2026-08-16` | — | 411,904 | 131,006 |

checked: 0 `user_id` values appear in more than one set, because a user's first render happens
once by construction.

## Leakage pass

| Prompt | Finding |
|---|---|
| Time | **LEAK-001** — `sessions_last_30d` was computed from a warehouse aggregate refreshed after the render. Feature removed 2026-09-19; see framing `## Features at inference`. |
| Join | none — only DC-001 is joined, on `account_age_days`, which is fixed at account creation and cannot encode the label |
| Duplicate | none — 0 `user_id` values cross a split boundary; near-duplicate detection on the feature vector found 41 exact repeats, all within the training set |
| Target | none — `theme` is excluded from the feature set by an explicit allow-list in `ml/features/spec.py`, asserted by `test/ml/test_feature_allowlist.py` |
| Group | none — the unit of prediction is one first render per user, so no entity has two rows |
| Preprocessing | **LEAK-002** — the `client_region` target-encoder was fitted on all rows in the first pass. Re-fitted inside the training fold only, 2026-09-21; the aggregate score fell 0.871 → 0.859, which is the size of the leak. |

## Metrics

### EVAL-001 — First-session switch rate against the incumbent

- **Metric:** proportion of first renders followed by a manual theme switch within 24h
- **Set:** test
- **Threshold:** at or below 0.70 × BASELINE-001's rate — the 30% reduction `proposal.md` names
- **Uncertainty:** analytic interval for a proportion, n = 411,904
- **Decides:** PROMO-001, and the G4 verdict
- **Serves:** REQ-007

### EVAL-002 — Accuracy against the best baseline

- **Metric:** accuracy
- **Set:** test
- **Threshold:** exceeds BASELINE-003 by more than the wider of the two intervals
- **Uncertainty:** bootstrap, 2,000 resamples over the test set, percentile interval
- **Decides:** PROMO-002
- **Serves:** REQ-007

| Candidate | EVAL-002 | Interval | vs BASELINE-003 |
|---|---|---|---|
| BASELINE-001 constant light | 0.612 | [0.601, 0.623] | — |
| BASELINE-003 header + hour | 0.847 | [0.838, 0.856] | — |
| GBM candidate | 0.859 | [0.850, 0.868] | **no difference** — intervals overlap by 0.006 |

|---|---|---|---|---|---|

| SLICE-008 region unresolved | DC-003 `client_region` null | 3,118 | 0.588 | underpowered, n = 3,118 | not comparable |

recorded as a G4 `--fail` on the candidate, independently of EVAL-002's "no difference".

## Operating point

Framing's cost table gives the two error costs as equal (one manual switch either way), so the
threshold that minimises expected cost is the one where the posterior odds are even: 0.500. The
arithmetic: cost(FP) = cost(FN) = 1 switch, so the optimal cut is `cost(FN) / (cost(FP) +
cost(FN))` = 0.500. Confusion counts on the test set at 0.500: TP 148,204 · FP 27,911 ·
FN 30,190 · TN 205,599.

## Anti-patterns

**The random split on time-series data.** `train_test_split(X, y, test_size=0.2)` on rows that
span six months. Yesterday's session is in the training set and today's in the test set, for
the same user. The score is excellent and it measures nothing. Split at a date.

**The leaked encoder.** `StandardScaler().fit(X)` before the split, or a target encoder fitted
on everything. The test set's statistics are in the training pipeline. Refit inside the fold,
and expect the score to fall — that fall is the size of the leak, and it is the true number.

**The bare number.** `Accuracy: 0.859 vs 0.847 baseline. Ship it.` Twelve thousandths with no
interval. The bootstrap says they overlap. Report the interval, then read it.

**The interval that is ignored.** The interval is computed, printed, and then the 0.012
difference is called a win anyway. The rule exists precisely for the moment it is inconvenient.
Write `no difference`.

**The test set read eleven times.** Every configuration checked against the test set, the best
one reported. The reported score is the maximum of eleven draws and will not reproduce. Log
every read; select on the validation set.

**Aggregate-only reporting.** One accuracy figure, no slices. The model is four points better
overall and eight points worse in the region with 6,000 users, and nobody knows until they
complain. Report every slice, including the underpowered ones with their counts.

**The dropped small slice.** `n = 3,118 — excluded from reporting as too small.` The exclusion
removes exactly the population least represented in the training data. Report it as
`underpowered` with its count and let the reader see the size.

**The default threshold.** `predict_proba > 0.5`, with a cost table saying a false negative
costs forty times a false positive. The model is well-calibrated and the decision is wrong.
Derive the cut from the costs.

**The unreproducible evaluation.** A notebook, a kernel that has been restarted, no seed, and a
dataframe read from a path that has since been overwritten. The number cannot be checked at
promotion, so promotion is refused. Write `## Reproduce` with all four.

## Validation

```bash
CHANGE=<name>
E=$(find delivery/changes/$CHANGE/specs/models -name evaluation.md 2>/dev/null | head -1)
test -n "$E" || echo "no evaluation.md under changes/$CHANGE/specs/models/"

for s in Splits "Leakage pass" Metrics Slices "Operating point" "Test-set reads" Reproduce; do
  grep -q "^## $s\$" "$E" || echo "$E: missing section '## $s'"
done

# All six leakage prompts are recorded
for p in Time Join Duplicate Target Group Preprocessing; do
  awk '/^## Leakage pass$/{on=1;next} /^## /{on=0} on' "$E" \
    | grep -q "^| $p " || echo "$E: leakage prompt '$p' is not recorded"
done

# Every EVAL-### carries all six fields
for id in $(grep -o 'EVAL-[0-9]\{3,\}' "$E" | sort -u); do
  body=$(awk -v id="$id" '$0 ~ "^### " id " " {on=1; next} /^### /{on=0} on' "$E")
  [ -n "$body" ] || continue
  for k in Metric Set Threshold Uncertainty Decides Serves; do
    printf '%s\n' "$body" | grep -q "\*\*$k:\*\*" || echo "$id: missing $k"
  done
  # Uncertainty names a method and a parameter
  printf '%s\n' "$body" | grep '\*\*Uncertainty:\*\*' \
    | grep -qE 'bootstrap|analytic|resamples|n *=' || echo "$id: uncertainty names no method or parameter"
done

# No result row carries a point estimate with no interval. Scoped to '## Metrics' and
# '## Slices' — the leakage pass quotes figures too, and they are not results. A row is a
# result row when it carries a decimal figure, so the header rows are skipped by construction.
awk -F'|' '/^## (Metrics|Slices)$/{on=1;next} /^## /{on=0}
           on && /^\| / && $0 ~ /[0-9]\.[0-9]/ {
             if ($0 !~ /\[[0-9.]+, *[0-9.]+\]/ && $0 !~ /underpowered/)
               print "row with a figure and no interval: " $2 }' "$E"

# No candidate read the test set twice
awk '/^## Test-set reads$/{on=1;next} /^## /{on=0}
     on && /^\| 20/ {split($0,c,"|"); gsub(/^ +| +$/,"",c[3]); n[c[3]]++}
     END{for (k in n) if (n[k]>1) print "test set read " n[k] " times for candidate: " k}' "$E"

# Reproduce names all four
for k in Command Seed "Data versions" Commit; do
  awk '/^## Reproduce$/{on=1;next} /^## /{on=0} on' "$E" \
    | grep -q "\*\*$k:\*\*" || echo "$E: '## Reproduce' is missing $k"
done

# The commit named in Reproduce exists in this repository
C=$(awk '/^## Reproduce$/{on=1} on && /\*\*Commit:\*\*/{print}' "$E" | grep -o '`[0-9a-f]\{7,40\}`' | tr -d '`')
[ -n "$C" ] && { git cat-file -e "$C^{commit}" 2>/dev/null || echo "Reproduce names commit $C, which is not in this repository"; }

# Any slice marked a regression must not sit under a G4 pass
grep -qi 'regression' "$E" \
  && grep '"gate":"G4"' delivery/.adlc/events.jsonl | tail -1 | grep -q '"verdict":"pass"' \
  && echo "G4 recorded as pass while a slice regression stands"

LANE=$(python3 -c 'import json;print(json.load(open("delivery/.adlc/state.json"))["lane"])')
[ "$LANE" = full ] || echo "lane is '$LANE' — G4 is enforced only on 'full'; re-propose before recording G4"
```

Each command prints nothing when the rule holds, except the lane check. The test-set read
counter and the interval check are the two that catch results which are real numbers arrived at
by a process that cannot support them.
