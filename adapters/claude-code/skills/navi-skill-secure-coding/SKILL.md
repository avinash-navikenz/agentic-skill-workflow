## When to use

Code is being written or reviewed that takes untrusted input, decides who may do something,
handles a credential, or implements a control a `THREAT-###` was dispositioned as `mitigated`.

## Rules

1. Implement every control the threat model names. A threat dispositioned `mitigated` names a
   control, a component and a test; that control is a `TASK-###` with an `Implements:` line,
   and its test is the one the threat's `Verify` line will run at G6.
2. Never assemble a query, a shell command, a file path, a URL or markup by concatenating
   untrusted input. Use the parameterised form the platform provides: bound parameters for
   SQL, an argument array with no shell for subprocesses, a path join followed by a prefix
   check for files, the URL builder for URLs, and an auto-escaping template for markup.
3. Validate every input at the boundary against the schema that describes it — see
   `navi-skill-api-design` — and reject what does not match rather than coercing it. An
   enumeration is an allowlist: an unlisted value is rejected, never mapped to a default.
4. Choose the encoding by where the value is going, not by where it came from. The same string
   needs different escaping in an HTML body, an HTML attribute, a URL parameter, a shell
   argument and a log line. "It was validated on the way in" is not an encoding.
5. Derive the acting identity from the verified session only. Never read a user id, tenant id,
   role or permission from a request body, query string, header or cookie that the caller
   controls.
6. Authorise the object, not the route. Every handler checks that the identity from rule 5 may
   act on the specific record it is about to read or write; a check that the caller is
   signed in is not a check that this record is theirs.
7. Fail closed. An unexpected error inside a validation, authentication or authorisation path
   denies the request. A `catch` that returns a permissive default converts an outage into an
   unauthorised access.
8. Keep secrets out of the source tree, the image, the logs and the error bodies. Read them at
   runtime from the platform's secret store — Azure Key Vault, GitHub Actions secrets, or the
   runtime's own injected environment — and rotate any credential that has ever been committed.
9. Write no cryptography and no token format. Use the platform's vetted primitive — the
   framework's session library, the standard library's password hash with its default
   parameters, the platform's JWT or PASETO implementation — and name the library and mode in
   the code. A home-made token, a custom HMAC scheme or a hand-rolled cipher mode is a defect
   regardless of how it is reviewed.
10. Generate every security-relevant value from a cryptographically secure source:
    `crypto.randomBytes`, `secrets.token_bytes`, `SecureRandom`,
    `RandomNumberGenerator.GetBytes`, `crypto/rand`. `Math.random`, `random.random`, `rand()`
    and any seeded generator are for tests and jitter, never for a token, an identifier, a
    salt or a key.
11. Redact at the log formatter, not at each call site. Credentials, tokens, full personal
    data and anything a threat model named as an asset are removed by the formatter, so a new
    log line cannot leak by omission. Log the identifier that lets an investigator find the
    record, not the record.
12. Bound every external call and every parse: a timeout, a maximum response size, and a
    maximum input size. An unbounded parse of attacker-supplied input is a denial of service
    with no exploit required.
13. Never instantiate a type named by untrusted input, and never deserialise untrusted data
    into a format that can construct arbitrary objects. Parse into a declared shape.
14. Write the regression test with the fix for every security defect, named so the threat
    model's `Verify` line can run it. `navi-skill-test-driven-development` owns the cycle; this
    rule says the test is not optional for a control.

## Decision table

| Observed construct or condition | Required replacement |
|---|---|
| SQL built with `+`, f-string, template literal or `%` | Bound parameters: `?`/`$1`/`:name`, values passed separately |
| `exec`, `system`, `shell=True` with an interpolated string | Argument array, no shell: `spawn(cmd, [args])`, `subprocess.run([...])` |
| A file path joined from request input | `resolve()` then reject unless the result is inside the allowed root |
| HTML assembled by string concatenation | Auto-escaping template; context-aware encoding for attributes and URLs |
| `innerHTML` set from any value that reached the client | `textContent`, or a sanitiser with an allowlist |
| A user id, tenant id or role read from the request | Derive it from the verified session; ignore the request's copy |
| A handler that checks only "is signed in" | Add the object check: may this identity act on this record |
| `catch` returning `true`, `allow`, or an empty permission set | Fail closed: deny, log, and surface the error |
| A credential, key or connection string in source or config in the repo | Secret store reference; rotate the committed value |
| A secret interpolated into a log line or an error message | Remove it; redact at the formatter |
| `Math.random`, `random.random`, `rand()` for a token, id, salt or key | The platform CSPRNG |
| A hand-written HMAC, cipher mode, or token format | The platform's vetted library, named in the code |
| A password stored with a general-purpose hash (MD5, SHA-256, unsalted) | The standard library's password hash at its default cost |
| An external call with no timeout | Add the timeout from the `CONTRACT-###`, plus a response size bound |
| `pickle`, `ObjectInputStream`, `BinaryFormatter`, `yaml.load` on untrusted data | Parse into a declared shape with a safe loader |
| A class or handler chosen by name from input | An explicit allowlist mapping input values to code paths |
| A `THREAT-###` dispositioned `mitigated` with no control in the diff | Blocking at review; the disposition claims something that does not exist |
| A security fix with no test | Add the regression test and name it in the threat's `Verify` line |

## Checklist

- [ ] Every `mitigated` threat's control exists in the diff, with its test
- [ ] No query, command, path, URL or markup is built by concatenating input
- [ ] Every input is validated against its schema at the boundary and rejected on mismatch
- [ ] Encoding is chosen by destination, not by the input's origin
- [ ] The acting identity comes from the session; no id, role or tenant is read from the request
- [ ] Every handler authorises the specific object it acts on
- [ ] Every validation, authentication and authorisation path fails closed
- [ ] No secret exists in source, image, log or error body; any committed one was rotated
- [ ] No hand-rolled crypto or token format; the library and mode are named in the code
- [ ] Every token, id, salt and key comes from a CSPRNG
- [ ] Redaction happens at the log formatter
- [ ] Every external call and parse has a timeout and a size bound
- [ ] Nothing untrusted names a type, a class or a handler
- [ ] Every security fix carries a regression test named in the threat's `Verify` line

## Anti-patterns

**Concatenated query.** `db.query("select * from users where email = '" + email + "'")`. One
apostrophe changes the statement. Use `select ... where email = $1` with the value bound.

**Validated therefore safe.** An email is checked against a regex on the way in, then
interpolated into HTML, a shell argument and a log line unescaped. Validation constrains the
value; it does not encode it for three different destinations. Encode at each one.

**Route-level authorisation.** `requireLogin()` on `/v1/orders/{order_id}` and nothing else.
Every signed-in user can read every order by changing the id. Check that the order belongs to
the session's identity.

**The trusting body.** `const userId = req.body.user_id` because the client already knows it.
The client also knows everyone else's. Take it from the session.

**Fail open.** `catch (e) { return { allowed: true } }` so an outage does not block users. The
first time the permission service is slow, everyone is an administrator. Deny and surface it.

**Secret in the repo, deleted later.** `API_KEY=sk_live_...` committed on Monday, removed on
Tuesday. It is in the history and it is still valid. Rotate it, then move it to the secret
store.

**`Math.random()` token.** A password-reset token generated from a predictable generator. The
next token is computable from the last few. Use `crypto.randomBytes`.

**The clever token format.** `base64(userId + ":" + sha256(userId + secret))`. Length
extension, no expiry, no rotation, no revocation. Use the platform's session or JWT library
and name the mode.

**Redaction at the call site.** Each log call remembers to strip the user id — except the one
added last Thursday. Redact in the formatter, where a new call site inherits it.

**Unbounded parse.** `JSON.parse(await res.text())` on an upstream response with no size cap
and no timeout. A slow, large response is a denial of service that needs no exploit. Bound
both, from the contract's `Timing`.

## Validation

```bash
# Concatenated SQL and shelled-out commands
grep -rnE "(select|insert|update|delete)[^\"']*[\"'][^\"']*\+|f\"[^\"]*(SELECT|INSERT)" src/
grep -rnE "(shell=True|child_process\.exec\(|Runtime\.getRuntime\(\)\.exec\()" src/

# Identity read from the request rather than the session
grep -rnE "req\.(body|query|headers|params)\.(user_?id|tenant_?id|role|is_?admin)" src/

# Non-cryptographic randomness in security paths
grep -rnE "(Math\.random|random\.random|new Random\(|math/rand)" src/ \
  | grep -viE "(jitter|backoff|test)"

# Fail-open catches
grep -rn -A3 "catch" src/ | grep -E "return (true|\{ *allowed: *true)"

# Secrets in the tree and in history
grep -rnEi "(api[_-]?key|secret|password|token)\s*[:=]\s*[\"'][A-Za-z0-9/+_-]{16,}" src/ config/
git log -p origin/main.. | grep -nEi "(api[_-]?key|secret)\s*[:=]\s*[\"'][A-Za-z0-9/+_-]{16,}"

# Every mitigated threat's named test exists
TM=delivery/changes/<name>/threat-model.md
grep -oE '[A-Za-z0-9_./-]+\.(spec|test)\.[a-z]+' "$TM" | sort -u | while read -r t; do
  test -e "$t" || echo "control test missing: $t"
done

# The pipeline's own static analysis. Semgrep ships via pip, brew or docker — the npm package
# of that name is a 517-byte placeholder that scans nothing and exits 0, so never reach it
# with npx. If semgrep is absent the check says so rather than passing.
if command -v semgrep >/dev/null 2>&1; then
  semgrep --config p/security-audit --error src/
else
  echo "static analysis did not run: semgrep is not installed (pip install semgrep, brew install semgrep, or the semgrep/semgrep image) — wire it into the pipeline or this step proves nothing"
fi
```

Each command prints nothing when the rule holds. The last check is the one G6 reads back: a
threat dispositioned `mitigated` whose test does not exist is a control that was described
rather than built.
